# Legacy 32-bit wire fixtures

Run against the pinned server checkout, on the Linux x86/x86-64 toolchain:

```
CXX=/usr/bin/g++ python3 tools/test-wire-compatibility/run.py --bits 64
CXX=/usr/bin/g++ python3 tools/test-wire-compatibility/run.py --bits 32
```

Requires Python 3.6+, the server's compatible C++17 compiler, pthreads and
32-bit C++ development libraries for `--bits 32`. The runner compiles the
actual repository Archive, NetworkId and PlayerQuestData sources into a
temporary executable; it neither regenerates nor edits production files.
It does not use Oracle, a server process or a network connection.

The oracle is explicit little-endian legacy x86 bytes and decoded state,
not a fixture generated by the implementation being tested. Literal fields
are annotated in fixtures.cpp. Counts, keys and values occupy four bytes;
NetworkId occupies eight, quest task masks two and booleans one. ADD is
zero. Quest relative-age indices are checked, not normalized: this process's
first quest pack constructs its temporary command at age 1, active quest
at age 2 and completed quest at age 3. No prior quest creation is allowed
before that test.

Covered: packed-map keys and values 0x80000000/0xffffffff in both directions;
active and completed quests with high-bit keys, task masks and reward flag;
AutoDeltaVector baseline 0xffffffff followed by two insertions and target 1,
which must yield [65,66] with baseline 1 using modulo-2^32 state arithmetic.
Each decoder is fed literal input, independently of its encoder.

Boundaries: not a captured historical executable trace; the oracle is a
manual transcription of the legacy32 format. Passing on both ABIs establishes
only these cases, not all packets, Windows compilation, gameplay, persistence,
or a live client's behavior. A separate client binary is not built here.
To include MissionListResponse, first build the server libraries from the
same checkout and ABI, then pass their build directory:

```
CXX=/usr/bin/g++ python3 tools/test-wire-compatibility/run.py --bits 64 --build-dir /path/to/build64
CXX=/usr/bin/g++ python3 tools/test-wire-compatibility/run.py --bits 32 --build-dir /path/to/build32
```

This adds three checks using the actual production mission classes and
serializers: an empty six-byte header, a manually specified two-entry
response, and decoding that literal response with no trailing bytes.
The optional link searches static libraries under the specified directory;
the caller must bind its identity to the tested checkout. An incompatible
ABI fails at link time. The harness does not rebuild these libraries.
Without `--build-dir` it explicitly prints NOT RUN for this family.

Standalone mode replaces only the server's crash-reporting Fatal routine
with stderr plus abort; no serializer, data class, primitive packing or
counter operation is replaced. The full-library mode uses the actual Fatal.
Broad malformed-input coverage and live-client behavior are not provided.
Existing full-message snapshot tests are separate.

The runner uses the production Linux defines, including lowercase `linux`,
which selects the conforming dependent-type declaration in AutoDeltaMap.

Historical-control boundary: upstream `22dd13d4a` compiled as32-bit passes
five standalone cases but fails packed-map unsigned text decoding because its
format specifiers do not match the uint32 arguments. The candidate corrects
that format contract. This case checks intended decimal values and literal
bytes; it does not assert parity with that upstream undefined formatting.
